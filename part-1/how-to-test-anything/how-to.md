# How to use these steps

[..go back](./README.md)

| Phase                    | What it is for                                                                      |
|--------------------------|-------------------------------------------------------------------------------------|
| **Learning goal**        | The one actionable thing you should be able to do after the step.                   |
| **1) Connections**       | Warm up: link the topic to what you already know; guess before you touch the code.  |
| **2) Concrete practice** | Grab the provided code and **try to test it with your current instincts**.          |
| **3) Concepts**          | _Now_ we name what you just did and give it a rule - the Sandi Metz heuristic.      |
| **4) Conclusions**       | Loop back to your guess, fill in your cell of the matrix, keep a one-line takeaway. |

## Why practice before concepts?

In the classic 4C order, concepts come before practice. We flip the middle two **on purpose**:

- You meet each kind of message by **trying to test it first**, using whatever mental model you already have.
- Then the Concepts section lands _on top of_ something you just knew right - often it simply **names** what you did, or
  gently corrects it. The rule sticks because you earned it.

## This is a testing session, not TDD

The production code is already written, in each language folder (e.g. [`javascript/src/`](./javascript/src)). Your time
goes into writing the **tests**.

## Working the prompts

Each step has inline prompts marked `> ✍ …`. Answer them in the learning log, in a scratch file, or out loud with a
pair - the **short timebox** matters more than the format. Where a prompt says "before you read on", honest guesses beat
polished ones: the point is to surface your real mental model before the concept arrives.
